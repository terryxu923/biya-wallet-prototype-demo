1. 产品概述

1.1 背景与目标

Biya Web3 钱包是内嵌于 BiyaPay App 的 Web3 钱包模块，支持 Privy Embedded 社交钱包，在 Ethereum、BSC 两条 EVM 网络上完成资产展示与收发闭环。

产品定位：

  1. Crypto 资产终端：在 Web3 首页展示有余额的链上 Crypto 资产（按网络白名单与余额规则过滤）
  2. Web2→Web3 桥梁：邮箱 / Google / Apple 社交登录 + 通行密钥 + Privy TSS，降低入链门槛
  3. 钱包自助管理：多社交钱包切换、本地排序、Privy 查看私钥、自定义名称/头像、退出登录

核心价值主张：让 BiyaPay 用户以最低门槛创建链上钱包，并在 ETH/BSC 上完成「看到资产 → 收款 → 付款」的最小闭环。

核心指标：

指标 说明
社交钱包创建完成率 从无钱包首页或添加钱包页完成验证码 + 通行密钥 + TSS 至进入 Web3 首页
注册 → 首笔发送转化率 创建成功后 7 日内完成至少一笔发送（ETH 或 BSC）
通行密钥绑定成功率 创建/登录流程中通行密钥验证一次通过率

1.2 核心设计理念

  • 社交单轨入链：邮箱 / Google / Apple（Privy Embedded，2-of-2 TSS：设备 + 服务商）；列表内可切换多个社交钱包；同一时刻仅一个活跃 Privy User，切换或签名前须完成对应账号登录（见 §2.5.2-Privy 登录态与多钱包）
  • 双链 EVM：网络白名单为 Ethereum、BSC；收发、复制地址、首页筛选均受此约束
  • 资产可见规则：仅展示链上 Crypto 资产，且 余额大于 0，且所属网络在白名单内；按网络筛选，不设代币 Symbol 级白名单
  • 首页行情数据（MVP）：Web3 首页 暂不接入单价与 24h 涨跌行情；法币估值与总余额在无行情时不计算（展示占位）；网络图标 由 API 写死 返回；币种图标 经 RPC 获取，无图则 Symbol 首字符默认图标
  • 安全分层：创建钱包、发送签名依赖 通行密钥；查看私钥通过 Privy 页面
  • 交易所首页与 Web3 分离：交易所首页承担 Web3 入口分流；钱包创建、资产、收发在 Web3 页面域完成（详见 §2.1-页面域划分）

2.5.2 Privy 登录态与多钱包

Flutter 端 同一时刻仅可操作一个活跃 Privy User。不同社交钱包可能绑定不同 Privy User，因此 切换钱包 与 提交签名 前须校验登录态；不做无感切换。

Symbol 不在上述比较范围内（如仅含特殊字符、且优先级 1–3 仍无法区分）：视为 无序，不强行指定顺序。

搜索 / 过滤：§5.3.2-搜索子层 等过滤后，在 结果子集 内 重新 执行本规则。

分层范围（X） 显示格式 精度规则 示例
X ≥ 1×10¹⁶ 科学计数法 2 位有效数字 1.23 × 10¹⁶

1 ≤ X < 10 动态 2–4 位小数 去尾 0 1.234 / 2.3
1×10⁻³ ≤ X < 1 动态有效小数 2–8 位有效数字 0.01234567
0 < X < 1×10⁻³ 极小数压缩表示 见下方规则 0.0₄12345 / 0.0₁₃12345
X = 0 固定显示 — 0
异常 / NULL 占位符 — ––

极小数压缩表示规则（0 < X < 1×10⁻³）：

  • 当小数点后连续 0 的个数 > 3 时（即第一个非零数字前的 0 个数 > 3），采用紧凑式：0.0ₙE
    • n = 小数点后连续 0 的个数（第一个非零数字前的 0 个数）
    • E = 从第一个非零数字起，取最多 5 位有效数字
    • 组合显示：0. + 下标 n + E
  • 当连续 0 的个数 ≤ 3 时，正常显示小数（保留 2–8 位有效数字）
